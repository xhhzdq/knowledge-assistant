# 第三周学习任务清单

> 主题：MySQL、Redis、Docker 与 Docker Compose  
> 项目主线：在第二周 FastAPI + PostgreSQL CRUD 的基础上加入缓存，并把运行环境容器化  
> 核心原则：PostgreSQL 继续作为主数据库；MySQL 是对比实验；每个阶段必须能够独立验收

## 1. 本周最终目标

第三周结束时，应能用一条 Compose 命令启动 Knowledge Assistant API、PostgreSQL 和 Redis，并能够解释容器、镜像、网络、数据卷、缓存一致性以及 PostgreSQL/MySQL 的主要差异。

目标运行链路：

```text
浏览器 / API Client
        │
        ▼
FastAPI 容器
  ├── PostgreSQL 容器：文档元数据，唯一事实来源
  └── Redis 容器：文档详情缓存和临时任务状态
```

本周必须形成四类产出：

- 可运行代码：Redis 缓存、Dockerfile、Compose 配置。
- 对比实验：同一组基础 SQL/ORM 行为在 PostgreSQL 和 MySQL 中的差异记录。
- 自动化验证：缓存命中、失效、TTL 和容器健康检查。
- 学习文档：MySQL、Redis、Docker、Compose 及第三周总结。

## 2. 范围边界

### 本周必须完成

- Docker 镜像与容器基础。
- 为 FastAPI 编写 Dockerfile 和 `.dockerignore`。
- 使用 Compose 启动 API、PostgreSQL 和 Redis。
- 使用命名卷持久化 PostgreSQL 和 Redis 数据。
- 使用 Redis 缓存文档详情，设置 TTL。

- 记录缓存命中、未命中、过期和失效测试。
- 完成 PostgreSQL 与 MySQL 的基础对比实验和文档。

- 不把 MySQL 替换为主数据库。
- 不同时维护 PostgreSQL 和 MySQL 两套生产数据。
- 不接入 Celery、RabbitMQ 或复杂分布式任务队列。
- 不实现 OCR、Embedding、Milvus 或 Reranker。
- 不做 Redis Cluster、哨兵或数据库主从高可用。
- 不做生产级 Docker 镜像安全加固和 Kubernetes。
- Nginx 留到最终部署周。

## 9. 阶段 4：文档详情 Cache Aside 缓存

### 设计范围

只缓存单文档详情：

```text
GET /documents/{id}
  → 查询 Redis
  → 命中：反序列化并返回
  → 未命中：查询 PostgreSQL
  → 写入 Redis，设置 TTL
  → 返回

PATCH /documents/{id}
  → 更新 PostgreSQL
  → 删除该文档缓存

DELETE /documents/{id}
  → 删除 PostgreSQL 和文件
  → 删除该文档缓存
```

不缓存列表接口，因为分页参数和数据变化会产生更多缓存 Key 与一致性问题。

### 需要学习

- Cache Aside 模式。
- 缓存命中、未命中、回源和失效。
- TTL 为什么是最后一道一致性保护，不替代主动失效。
- 缓存穿透、击穿和雪崩的基本概念。
- JSON 序列化、Key 设计和版本前缀。
- Redis 故障时是让请求失败，还是降级查询 PostgreSQL。

### 建议 Key

```text
knowledge-assistant:document:v1:{document_id}
```

### 代码任务

- 增加 Redis 配置和客户端依赖。
- 抽象最小 `DocumentCache` 接口，避免 Service 直接散落 Redis 命令。
- 实现读取、写入和删除缓存。
- 为详情设置明确 TTL，例如开发阶段 300 秒。
- Redis 不可用时记录 warning，并降级查询 PostgreSQL。
- 不缓存不存在的文档，第一版先接受穿透，文档中记录改进方案。

### 测试任务

- 第一次查询未命中并写入缓存。
- 第二次查询命中缓存，不再查询 Repository。
- TTL 已设置且大于 0。
- PATCH 后旧缓存被删除。
- DELETE 后缓存被删除。
- Redis 异常时仍可从 PostgreSQL 返回数据。
- 缓存内容不包含服务器内部路径。

### 产出

- Redis 客户端和缓存模块
- Cache Aside 集成测试
- `docs/week03/Redis缓存模式与一致性.md`

### 验收标准

- [ ] 能观察到第一次未命中、第二次命中。
- [ ] 修改后不会读到旧名称或旧状态。
- [ ] 删除后不会从缓存返回已删除文档。
- [ ] Redis 停止时 API 仍能查询 PostgreSQL。

## 10. 阶段 5：PostgreSQL 与 MySQL 对比实验

### 定位

MySQL 是独立兼容性实验，不改变 PostgreSQL 主线。先比较，再决定是否值得让全部 Repository 和迁移兼容两种数据库。

### 需要学习

- MySQL Server、数据库、用户和权限。
- InnoDB、事务和行级锁基础。
- `utf8mb4` 字符集与排序规则。
- 自增主键、UUID、时间类型、布尔类型和 JSON 类型。
- PostgreSQL 与 MySQL 在 SQL 方言、索引、约束、`RETURNING`、UPSERT 和 JSON 查询上的差异。
- SQLAlchemy 方言如何屏蔽一部分差异，以及哪些差异无法自动屏蔽。

### 实验任务

1. 用容器启动 MySQL 8，不安装到宿主机。
2. 创建独立实验数据库和用户。
3. 创建与 `documents` 含义相同的实验表。
4. 插入包含中文、时间、状态和 UUID 的记录。
5. 比较分页、唯一约束、事务回滚、时间字段和 JSON 查询。
6. 记录现有 SQLAlchemy Model/Alembic 迁移直接切换 MySQL 时遇到的问题。
7. 只在改动很小且不破坏 PostgreSQL 时增加 MySQL Repository 冒烟测试；否则保留为独立 Demo，并说明原因。

### 产出

- 可重复执行的 MySQL 实验步骤或 SQL
- `docs/week03/PostgreSQL与MySQL差异对比.md`
- 是否让主项目支持双数据库的技术结论

### 验收标准

- [ ] 能解释 PostgreSQL 和 MySQL 各自适合的场景。
- [ ] 能列出至少五项与本项目直接相关的差异。
- [ ] 实验不会修改 PostgreSQL 开发数据。
- [ ] 不为了“支持两种数据库”复制两套业务代码。
